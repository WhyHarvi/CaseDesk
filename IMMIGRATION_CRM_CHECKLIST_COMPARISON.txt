CASEDESK IMMIGRATION CRM - CURRENT SYSTEM COMPARISON

Comparison date: July 15, 2026

STATUS MEANING

AVAILABLE = The main prototype workflow exists in the backend and user interface.
PARTIAL = Useful functionality exists, but important prototype steps are missing.
MISSING = The workflow is not currently usable.

OVERALL RESULT

CaseDesk already has a large part of a usable Immigration CRM.

The strongest areas are:
- Case creation and case profiles
- Immigration assessments
- Case workflows and tasks
- Document management
- Immigration forms and form versions
- Agreements, letters, and document writing
- Staff communication tools
- Follow-ups, appointments, payments, and statements

The main items still required before real prototype use are:
- Support the intended employee roles, especially Manager and Staff
- Add duplicate checking when creating clients
- Complete applicant and dependant editing
- Add client portal document upload and portal messaging
- Improve the employee dashboard with tasks, appointments, and missing documents
- Add basic case reports and filters
- Prevent unsafe deletion of important records and history
- Test one complete immigration case from creation to closure


1. USER ACCESS AND AGENCY SEPARATION

Status: PARTIAL

Already available:
- Secure Supabase login and invitation setup exist.
- Admin, Consultant, and Client accounts can log in.
- Agency membership is loaded by the backend from the authenticated user.
- Client, case, document, form, communication, and payment queries are agency scoped.
- Client portal users are linked to their own client record.
- Tenant isolation and authorization tests exist.

Still needed:
- Manager and Staff roles exist in the database but authentication rejects them.
- Define simple permissions for Admin, Manager, and Staff.
- Allow Admin to create and manage all intended employee roles, not only Consultants.
- Add Manager access to all agency cases and employee activity.
- Confirm every route follows the same role rules.


2. CLIENT MANAGEMENT

Status: PARTIAL

Already available:
- Create, list, view, update, and delete client operations exist.
- Client profile shows cases, documents, follow-ups, payments, notes, and activity.
- Clients can be assigned to an employee.
- Client search and filtering are available in the interface.

Still needed:
- Check phone and email for duplicates before creating a client.
- Add normalized phone and email fields for reliable matching.
- Add important profile fields such as preferred language and identification details.
- Add a visible client number if the agency needs one for daily searching.
- Replace normal permanent deletion with archive or inactive behavior.
- Warn before deleting a client that has cases, documents, payments, or history.


3. CASE MANAGEMENT
    
Status: MOSTLY AVAILABLE

Already available:
- Create, list, view, update, and delete case operations exist.
- A case stores client, case type, stage, status, assigned employee, next action, submission date, and decision date.
- Case profiles bring together assessment, workflow, applicants, documents, forms, appointments, communication, notes, follow-ups, and payments.
- Case changes are recorded through the general activity system.
- Cases can be assigned to a primary or supporting employee.

Still needed:
- Add a clear case priority field.
- Add a visible case number if required for office use.
- Restrict reassignment according to the final Admin and Manager permissions.
- Use controlled case statuses instead of accepting inconsistent free-text values.
- Prefer archive or close over permanent case deletion.
- Require a next action or pending task for every active case.


4. APPLICANTS AND FAMILY MEMBERS

Status: PARTIAL

Already available:
- Immigration profiles support primary applicants and related applicants.
- Applicant fields include identity, relationship, passport, contact, immigration, education, employment, travel, family, and other profile information.
- Applicants can be listed and added from the case profile.

Still needed:
- Add an update applicant operation and editing interface.
- Add a safe remove or deactivate applicant action.
- Prevent accidental duplicate applicants on the same case.
- Clearly enforce one primary applicant per case.
- Confirm applicant information can be reused safely across related cases.


5. IMMIGRATION PROFILE AND ASSESSMENT

Status: MOSTLY AVAILABLE

Already available:
- A detailed case assessment workspace exists.
- The system stores immigration history, education, work, language, family, travel, eligibility, risk, and recommendation information.
- Assessment changes are saved to the case and linked to the employee.
- The assessment can support document checklists and form autofill.

Still needed:
- Show a clear final assessment result and completion date in one summary area.
- Record who formally completed or approved the assessment.
- Preserve previous finalized assessments or add assessment version history.
- Prevent important completed assessments from being overwritten without history.


6. CASE WORKFLOW AND TASKS

Status: MOSTLY AVAILABLE

Already available:
- Workflow templates can be created and applied to cases.
- Case workflow steps show pending and completed work.
- Standalone case tasks can be created, updated, assigned, prioritized, completed, and deleted.
- Tasks can contain due dates and assigned employees.
- The case profile includes workflow and task workspaces.

Still needed:
- Add a simple Cancelled task state instead of relying on deletion.
- Make overdue state consistent everywhere.
- Prevent an active case from having no next action or pending task.
- Record task reassignment, cancellation, and completion consistently in the timeline.
- Avoid deleting completed tasks that form part of the case history.


7. FOLLOW-UPS, REMINDERS, AND APPOINTMENTS

Status: MOSTLY AVAILABLE

Already available:
- Follow-up create, view, update, complete, and delete operations exist.
- Follow-ups support assigned employees, due dates, status, and completion time.
- Appointments can be created, updated, completed, cancelled, and deleted.
- The case profile contains follow-up and appointment interfaces.
- The dashboard shows due follow-ups.

Still needed:
- Clearly separate due-today and overdue follow-ups on the main dashboard.
- Add a missed or no-show appointment outcome.
- Require a next action after a missed appointment.
- Add simple in-app reminders for assigned work.
- Prefer cancellation over deleting follow-ups and appointments with history.


8. NOTES AND ACTIVITY TIMELINE

Status: PARTIAL

Already available:
- Internal client and case notes can be created, viewed, edited, and deleted.
- Activity logs exist for client and case actions.
- Case activities are displayed in the case profile.
- Communication and form modules maintain additional audit records.

Still needed:
- Create one clear combined chronological case timeline.
- Make the employee name, action, date, and affected record visible for every important event.
- Prevent normal users from silently editing or deleting important completed history.
- Add explicit history entries for reassignment, closure, document review, and major status changes.
- Replace the placeholder Activity Logs settings screen with a working viewer.


9. DOCUMENT MANAGEMENT

Status: AVAILABLE WITH SMALL GAPS

Already available:
- Documents can be requested, created, uploaded, downloaded, previewed, updated, and finalized.
- Document statuses include Requested, Uploaded, Under Review, Changes Requested, Approved, Finalized, and Not Required.
- Documents link to the correct agency, client, case, uploader, and reviewer.
- Internal and Client visibility options exist.
- Shared and agency document libraries exist.
- Document checklists can be generated for a case.

Still needed:
- Let clients upload requested documents directly from the normal client portal.
- Make replacement requests and review comments very clear to the client.
- Confirm all important document deletions are blocked or archived after approval/finalization.
- Add a simple file-size and accepted-file-type message in every upload screen.


10. IMMIGRATION FORMS

Status: AVAILABLE

Already available:
- Forms can be assigned from a catalog or uploaded as custom forms.
- Form status, source, requirement, version, and revision information are stored.
- Form autofill uses saved case and applicant information.
- Browser copies, uploaded copies, official imports, and restored versions are supported.
- Review comments, corrections, approvals, signatures, finalization, locking, audit, and version restoration exist.
- Finalized forms remain attached to the case.

Still needed before live use:
- Test the most common immigration form types with real sample data.
- Confirm autofill mappings for primary applicant, spouse, and dependants.
- Make unsupported PDF or XFA limitations clear to staff.


11. AGREEMENTS AND LETTERS

Status: AVAILABLE

Already available:
- Agreement and letter templates can be created and versioned.
- Templates can create case-specific drafts.
- Custom correspondence drafts can be created.
- The document writer supports editing and saving versions.
- Issued documents can be saved as finalized client documents.
- Creation, update, issue, and version information are recorded.

Still needed before live use:
- Test the standard service agreement and common client letters.
- Confirm merge fields work for client, case, and agency information.
- Decide which issued documents are client-visible by default.


12. CLIENT COMMUNICATION

Status: AVAILABLE WITH CONFIGURATION REQUIRED

Already available:
- Communication conversations and messages support Email, SMS, Chat, and Call channels.
- Draft, send, retry, delivery status, inbox, consent, attachment, template, and audit functionality exists.
- Communication is linked to the agency, client, and case.
- Internal and client-facing directions are separated.
- Manual communication import and communication history are supported.
- Mail and Ooma settings interfaces exist.

Still needed before live use:
- Configure and test the agency's real email or SMS provider.
- Test incoming and outgoing communication for one real case.
- Confirm failed delivery messages are visible to staff.
- Provide a simple manual Log Call or Log External Message action if it is not obvious in the interface.


13. CLIENT PORTAL

Status: PARTIAL

Already available:
- Admin or an authorized Consultant can invite a client.
- The client can log in securely.
- The portal shows the client's applications, stages, next actions, visible documents, and profile.
- Portal queries only use the linked client's records.
- A separate secure client chat link supports messages.

Still needed:
- Add document upload to the normal authenticated client portal.
- Allow the client to open or download visible files.
- Integrate client messaging into the normal portal instead of relying only on a separate chat link.
- Show document review comments and replacement instructions.
- Decide whether the client can update profile information or only view it.
- Add a clear client view of appointments and requested actions.


14. FEES AND PAYMENTS

Status: MOSTLY AVAILABLE

Already available:
- Admin can create, update, list, and delete payment records.
- Records store total fee, paid amount, balance, payment status, and notes.
- Payments link to clients and cases.
- Client and case profiles display payment information.
- Statements of account can be filtered, generated, saved, previewed, and exported as PDF.
- Refunds and adjustments are represented in account statements.

Still needed:
- Confirm whether one payment record represents an agreement, invoice, or actual payment.
- If needed, separate charges from individual payment transactions.
- Prevent silent deletion of financial history.
- Record who created or changed each financial entry.
- Test partial payment, refund, and adjustment workflows from the UI.


15. EMPLOYEE DASHBOARD

Status: PARTIAL

Already available:
- Dashboard shows total clients, active clients, open cases, due follow-ups, pending payments, pipeline stages, and recent records.
- Consultant access is scoped to assigned clients and cases.
- Follow-up and workload pages exist.

Still needed:
- Show tasks due today and overdue tasks.
- Show upcoming appointments.
- Show missing or changes-requested documents.
- Show cases waiting for an employee update.
- Clearly separate today's work from overdue work.
- Ensure every dashboard item opens the correct client, case, task, or follow-up.


16. SEARCH AND NAVIGATION

Status: MOSTLY AVAILABLE

Already available:
- Client and case list pages include search, filters, sorting, and profile navigation.
- Cases can be filtered by client, type, stage, status, and assigned employee in the interface.
- Global navigation includes clients, cases, follow-ups, documents, payments, workload, and settings.

Still needed:
- Add client numbers and case numbers if the agency uses them operationally.
- Confirm search works well when the agency has hundreds or thousands of records.
- Move important search filters to backend queries instead of loading too many records into the browser.
- Add one simple global search if staff frequently search across clients and cases.


17. BASIC REPORTS AND MANAGEMENT VIEW

Status: PARTIAL

Already available:
- Dashboard provides basic client, open-case, pipeline, follow-up, and payment totals.
- Workload shows employee case responsibility.
- Payment and statement pages provide financial information.
- Lead reports exist separately for lead intake.

Still needed:
- Add a basic case report for active, completed, closed, and overdue cases.
- Show cases by case type, stage, and assigned employee.
- Show overdue tasks, follow-ups, and outstanding document requests.
- Add simple date, employee, case type, stage, and status filters.
- Add a basic collected-fees and outstanding-balance summary.
- Allow Admin or Manager to export a simple case report.


18. BASIC SYSTEM CONTROLS

Status: PARTIAL

Already available:
- Admin can manage Consultants.
- Workflow, document, form, correspondence, and communication templates exist.
- Activity-log APIs exist.
- Central error handling, rate limiting, and production security middleware exist.
- Important creation workflows use database transactions in several modules.

Still needed:
- Manage Manager and Staff accounts, not only Consultants.
- Replace placeholder settings sections with working agency and activity-log controls.
- Add clear protection against double-click duplicate submissions to critical forms.
- Archive important records instead of permanently deleting them.
- Add a simple database backup procedure before real client data is entered.


OPTIONAL LEAD AND INTAKE FEATURES

Status: STRONG FOUNDATION, NOT REQUIRED TO FINISH THE CORE CRM PROTOTYPE

Already available:
- Manual lead entry, Quick Add, website forms, CSV import, and provider webhooks.
- Lead dashboard, reports, qualification, consultations, commercial tracking, and conversion to a client and case.

Still incomplete:
- Manual lead duplicate checking against leads and clients.
- General lead contact, reassignment, follow-up, and lost actions.
- Manager and Staff access to lead workflows.


MINIMUM WORK RECOMMENDED BEFORE PROTOTYPE LIVE USE

Priority 1 - Required access and data safety
1. Support Admin, Manager, and Staff roles with clear case permissions.
2. Add client duplicate checking by normalized phone and email.
3. Replace dangerous client, case, task, document, payment, and history deletion with archive or cancellation where appropriate.

Priority 2 - Complete daily immigration case work
4. Add applicant editing and safe removal.
5. Add clear task overdue and cancelled states.
6. Add a combined case activity timeline.
7. Add tasks, appointments, missing documents, and overdue work to the employee dashboard.

Priority 3 - Complete the client experience
8. Add authenticated portal document upload and download.
9. Add portal messaging, appointments, and requested-action display.
10. Confirm internal notes and internal documents never appear in the portal.

Priority 4 - Management and verification
11. Add a simple case report with essential filters.
12. Complete the Admin activity-log viewer.
13. Test payment, refund, adjustment, and statement workflows.
14. Run the complete case lifecycle test below.


PROTOTYPE RELEASE TEST

The system is ready for controlled prototype use when all of these pass:

1. Admin creates an employee and the employee logs in.
2. The employee cannot access another agency's records.
3. The employee creates a client and duplicate checking prevents a second copy.
4. The employee creates a case and adds the primary applicant and dependant.
5. The employee completes an assessment and starts the case workflow.
6. Tasks, follow-ups, and appointments appear on the correct dashboard day.
7. The client receives a portal invitation and logs in.
8. The client uploads a requested document.
9. Staff reviews the document and requests a replacement.
10. Staff completes, reviews, and finalizes an immigration form.
11. Staff creates and issues a service agreement or letter.
12. Staff records a call, internal note, and client message.
13. Staff records a fee and payment and generates a statement.
14. Admin or Manager sees the complete case history and basic report.
15. Staff closes the case without deleting its history.


FINAL ASSESSMENT

The current system is beyond an early mock-up and already contains most major Immigration CRM modules.

It is not yet ready for real prototype users because several important workflows are incomplete at their edges: employee roles, duplicate-safe client creation, applicant editing, portal uploads, management reporting, and history protection.

Once the Priority 1 to Priority 4 items above are completed and the full release test passes, the system should be suitable for controlled prototype use by a small immigration agency.
