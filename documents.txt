The Documents tab has a strong visual foundation, but several important workflow and production-readiness items remain. No code was changed during this review.

## Highest priority

1. **The “Secure Upload Link” is currently not functional**

The URL is generated in the browser using the current timestamp. There is no backend token, expiration, upload route, or validation behind it. [DocumentsWorkspace.jsx](/Users/harvi/Emerks/casedesk/frontend/src/components/case-profile/DocumentsWorkspace.jsx:307)

Implement:

- Cryptographically secure token stored as a hash.
- Associated agency, client, case, and requested documents.
- Expiration and revocation.
- Public client-upload page.
- Rate limiting and upload scanning.
- Ability to assign uploaded files to checklist requirements.

Until that exists, the option should be labelled “Coming soon” or hidden because it currently appears secure but is not.

2. **Cases only load the first 25 documents**

The backend list endpoint defaults to 25 results, while a checklist can contain up to 150. The Case Profile requests documents without pagination, so documents after the first 25 may silently disappear. [CaseProfile.jsx](/Users/harvi/Emerks/casedesk/frontend/src/pages/CaseProfile.jsx:593)

Either:

- Fetch all case documents using pagination, or
- Add a dedicated case-document endpoint that returns the complete case checklist.

3. **Finalize needs a dedicated backend operation**

Currently finalization is a generic PATCH that sets `status: Reviewed` and a client-provided timestamp. This means other interfaces can mark an empty record reviewed without actually reviewing a file. [CaseProfile.jsx](/Users/harvi/Emerks/casedesk/frontend/src/pages/CaseProfile.jsx:614)

Create something like:

```text
POST /client-documents/:id/finalize
```

It should verify:

- A stored file exists.
- The document is not already finalized.
- The user has review permission.
- `reviewedAt` is generated by the server.
- `reviewedById` is recorded.
- A meaningful audit event is created.

## File versions

Replacing a file currently deletes the previous stored file. That is risky for legal case records. [clientDocumentController.js](/Users/harvi/Emerks/casedesk/backend/src/controllers/clientDocumentController.js:144)

Add a `DocumentVersion` model containing:

- Version number.
- Storage key.
- Original filename.
- File size and MIME type.
- Uploaded by and uploaded date.
- Replacement reason.
- Current-version indicator.
- Hash/checksum.

Finalized documents should preserve exactly which version was approved.

## Security and storage

Before production, these need attention:

- Authentication currently falls back to the first agency and first user when headers are absent. [authMiddleware.js](/Users/harvi/Emerks/casedesk/backend/src/middleware/authMiddleware.js:4)
- There are no role checks for deleting documents, finalizing files, or modifying the Shared Library.
- MIME type is accepted from the browser; verify file signatures instead.
- Add malware scanning and quarantine before files become downloadable.
- Local filesystem storage will not work reliably across multiple server instances.
- Move production files to private object storage with encryption, backups, retention rules, and short-lived signed URLs.
- Record downloads, previews, replacements, finalization, and deletion in the audit trail.

## Shared Library

The backend foundation exists, but the frontend is still incomplete:

- It still shows View, Download, and Delete buttons directly in each row.
- Deletion has no custom confirmation.
- Backend editing exists, but there is no frontend edit action.
- No search, category filtering, sorting, or pagination.
- No “Add to this case” action.
- No library access permissions.
- No protection against deleting a resource actively used elsewhere.

The most useful Shared Library action would be:

```text
Open resource → Add copy to My Documents / Add as client requirement
```

Recommended work:

- Edit an existing written document.
- Autosave drafts.
- Save vs Save As.
- Version history.
- Unsaved-changes warning.
- Template insertion.

- Generate a genuine DOCX or PDF instead of HTML saved with a `.doc` extension.

## Duplicate document interface

There is also a separate global Documents page with different terminology:

- `Received` is displayed as “Verified.”
- `NotRequired` is displayed as “Archived.”
- It permits manually editing review dates and statuses.
- It uses a browser `window.confirm` delete dialogue.

[Documents.jsx](/Users/harvi/Emerks/casedesk/frontend/src/pages/Documents.jsx:93)

This should either be rebuilt using the same document components and lifecycle or removed. Maintaining two conflicting document systems will produce inconsistent records.
